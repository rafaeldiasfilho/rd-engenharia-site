## 1. Strict stack

| Layer | Choice (installed version) |
|---|---|
| Language | JavaScript (ES modules, JSX); TypeScript only in the 3 files in `src/components/ui/` |
| UI | React 18.3.1 + react-dom, functional components and hooks |
| Build | Vite 5.4.x + `@vitejs/plugin-react`; static prerender in `scripts/prerender.mjs` |
| Styles | Plain CSS in `src/styles.css` (theme variables in one block, light and dark); self-hosted Manrope in `public/fonts/` |
| 3D | three 0.170.0, lazy-loaded per scene (`src/scenes3d/`) |
| Icons | `@phosphor-icons/react`, wrapped by `src/Icon.jsx` |
| Database and auth | Supabase (Postgres + RLS + Auth). `@supabase/supabase-js` 2.x only in `/admin`; the public site uses plain `fetch` |
| Analytics | `@vercel/analytics` (WhatsApp click event) |
| Share images | `@resvg/resvg-js` in `scripts/og.mjs` → `public/og/` (committed) |
| Tests | Vitest 2.1.9 (`npm test`), Node environment, mocks only |
| Hosting | Vercel, Git deploys from `main`; clean URLs, redirects and headers in `vercel.json` |

**Forbidden** (removed on purpose or never wanted):
- Tailwind CSS, shadcn runtime helpers (`cn()`, `clsx`, `tailwind-merge`): removed in the 2026-11-06 cleanup.
- CSS-in-JS and UI kits (MUI, Chakra, styled-components).
- Router libraries: routing is one HTML file per page plus `findPage(slug)` in `src/main.jsx`.
- State libraries (Redux, Zustand), jQuery, Moment.js.
- `@supabase/supabase-js` on public pages (keep them light: use `src/publicApi/api.js`).
- Any server-side code or a Supabase `service_role` key in this repository.
- New dependencies without a clear need: the project keeps few dependencies on purpose.

## 3. Database schema (summary)

Supabase project "RdEngenharia". Source of truth: `supabase/schema.sql` (size and format constraints live in the applied migrations). Table and column names are Portuguese and **must not be renamed** from the code.

| Table | Fields | Access (RLS) |
|---|---|---|
| `equipe` | `email` text PK | no policy: managed only in the SQL editor |
| `clientes` | `id` uuid PK, `nome` text!, `tipo` enum `pf`/`pj`, `documento`, `contato`, `telefone`, `whatsapp`, `email`, `cep`, `logradouro`, `numero`, `bairro`, `cidade`, `uf` (default SP), `origem`, `observacoes`, `aceita_lembretes` bool!, `aceite_lembretes_em` date, `criado_em` timestamptz | team only (`eh_equipe()`) |
| `servicos` | `id` uuid PK, `cliente_id` uuid FK → `clientes.id` (on delete cascade), `tipo` text!, `descricao`, `local_servico`, `status` enum `orcamento`/`em_andamento`/`concluido`, `data_realizacao` date, `repetir_meses` int > 0, `vencimento` date, `encerrado` bool!, `art_numero`, `valor` numeric(12,2), `observacoes`, `criado_em` | team only |
| `lembretes_site` | `id` uuid PK, `nome`!, `whatsapp`!, `documento`!, `vencimento` date, `consentimento` bool!, `consentimento_em`, `tratado` bool!, `criado_em` | `anon`: INSERT only, only the 5 columns `nome, whatsapp, documento, vencimento, consentimento`, with `consentimento = true` and `tratado = false`; team: all |

Function `eh_equipe()` (security definer): true when the JWT e-mail is in `equipe`. Executable by `authenticated` only.

## 4. API contracts

There is no own backend. The only calls are to Supabase.

### Public: create a reminder (`src/publicApi/api.js` → `sendReminder`)
- `POST {SUPABASE_URL}/rest/v1/lembretes_site`
- Headers: `apikey` and `Authorization: Bearer` with the publishable key, `Content-Type: application/json`, `Prefer: return=minimal`.
- Body: `{ "nome", "whatsapp" (digits, with 55), "documento", "vencimento" ("YYYY-MM-DD", last day of the month, or null), "consentimento": true }`.
- Response: `201` with no body → resolves. Any non-2xx → throws `Error("falha")`. Network error → rejects.
- Code-side names are English (`name, whatsapp, document, expiry, consent`); the mapping to Portuguese columns happens only here.

### Internal (`src/admin/db.js` → `openDatabase()`)
Returns `{ mode: "supabase" | "demo" | "unavailable", auth, clients, services, reminders }`.
- `auth.session()` → `{ email }` or `null`; `auth.signIn(email, password)` → `{ email }` or throws "E-mail ou senha incorretos."; `auth.signOut()`.
- Each table (`clients` → `clientes` ordered by `nome`; `services` → `servicos` and `reminders` → `lembretes_site`, newest first): `list()`, `save(item)` (upsert; empty strings become `null`; no `id` means insert), `remove(id)`. Supabase errors are thrown as `Error(message)`.

### Configuration
- `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` (Vercel env; fall back to the public values in `db.js`). The publishable key is public by design; RLS protects the data.
- `VITE_DEMO=1` with `npm run dev` → demo mode (browser `localStorage` only).

## 5. Commands and checks

```bash
npm install
npm run dev        # development server
npm test           # unit tests (Vitest), no network
npm run build      # vite build + prerender: 25 HTML pages, sitemap.xml, llms.txt
npm run preview    # serve dist/
```

Daily cycle (owner's method): read the PRD → update this file if a table or API changes → build the change in a small isolated file → `npm test` and `npm run build` until both pass → review `git diff --cached` → owner approves before any push to `main`.
